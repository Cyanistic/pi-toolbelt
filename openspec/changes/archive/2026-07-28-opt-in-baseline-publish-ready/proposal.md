## Why

Toolbelt is not honest enough to publish: any valid config (including `{}`) clamps the session to a built-in six-tool baseline, missing config parks discovery in a half-dead inactive mode, and public docs still describe removed commands and a deferred settings UI that already shipped. Before a first public release, hiding must be opt-in, install-without-config must be useful, and package/docs surfaces must match the product.

## What Changes

- **BREAKING**: Root default baseline becomes unrestricted (everything). Omitting `baseline` through the full inherit chain no longer applies the built-in six-tool list.
- **BREAKING**: `baseline` accepts JSON `null` as explicit unrestricted. Non-empty and empty arrays remain exact allowlists (`[]` means zero tools; honored, not rejected).
- **BREAKING**: No config file is treated as default config (unrestricted baseline, BM25 search). `query_tools` and `manage_tools` work after install without writing `toolbelt.json`. Missing-file "inactive" as the normal install path goes away.
- `session_start` applies `setActiveTools` only when the resolved baseline is an array. Unrestricted baseline leaves the host active set untouched.
- `/toolbelt reset` restores an array baseline, or activates all currently registered tools when baseline is unrestricted.
- Settings UI exposes Default/Inherit (omit), Unrestricted (`null`), and Custom (list), parallel to how search distinguishes default vs explicit BM25. Project keeps both Inherit and Unrestricted so a global list can be overridden.
- Invalid config with a valid session snapshot stays session-only (no behavior change to that fail-soft path).
- Rewrite README for strangers: `pi install npm:pi-toolbelt`, current commands, honest baseline/search semantics. Remove `/toolbelt setup`, the false settings-deferred roadmap, and quality/benchmark promises.
- Add repo `docs/` (config, commands, behavior) linked from README. Keep `docs/` in git only; do not add it to npm `files`.
- Package polish for publish: real MIT `LICENSE`, `repository`/`homepage`/`bugs`, `engines.node` `>=20`, and `files` only lists what exists. Pin git-cliff as a development dependency and provide non-writing preview plus a local `release:prepare -- <version>` command. This change establishes and verifies the tooling; the subsequent first-publish workflow generates `CHANGELOG.md`, updates release metadata, inspects the package, and performs the manual release steps.
- Delete `.rpiv/guidance/` and fix `AGENTS.md` so invariants and pointers match code (including dropping the false "additive-only / reset is sole removal" claim).
- OpenSpec tasks that touch behavior also require matching README/`docs/` updates so docs cannot lag the contract.

## Capabilities

### New Capabilities

- None. Publish packaging and user docs are delivery requirements of this change, not separate runtime capabilities.

### Modified Capabilities

- `interactive-toolbelt-management`: Baseline resolution (omit / null / array including empty), default = unrestricted, settings baseline modes, reset semantics, status copy, and no-config-as-default for management surfaces.
- `autonomous-tool-discovery`: Runtime enablement when no config file exists (default config, discovery on); alignment of configured vs degraded modes with the new baseline model. Session-only-on-invalid-config-with-snapshot remains.

## Impact

- **Code**: `src/schemas.ts`, `src/types.ts`, `src/constants.ts`, `src/config.ts`, `src/index.ts` (`session_start`), `src/commands.ts` (reset/status/help), `src/settings-ui.ts` (baseline mode picker and drafts).
- **Docs / repo**: `README.md`, new `docs/**` including release instructions, `AGENTS.md`, delete `.rpiv/guidance/**`, `LICENSE`, `cliff.toml`, and a local release-preparation script. `CHANGELOG.md` is generated by that tooling during the subsequent first-publish workflow, not by this pre-publish change.
- **Package**: `package.json` metadata, scripts, development dependency, and `files`; version stays `0.1.0` for first public cut. Commit, annotated tag, push, and `npm publish` remain explicit operator steps.
- **Host / users**: First-time install no longer requires config to use discovery; existing users who relied on omit-baseline → six-tool clamp must set an explicit array. Extension disable remains pi host concern (`pi config` / packages), not a toolbelt.json kill switch.
- **Verification**: Manual E2E via real Pi, including pre-publish `pi install <local package path>` (not only `pi -e`). No new automated test suite.
- **Out of scope**: Scoped package rename, gallery assets, CONTRIBUTING/COC, CI-for-tests, public quality benchmarks, inventing a toolbelt-level full extension disable flag, release PRs, automatic version selection, automatic publishing, prerelease support, and GitHub Release automation.
