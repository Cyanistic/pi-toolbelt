## 🟡 Important

### I1 🟡 Reset-marker producer-consumer contract broken by empty catch

**Where**
`src/commands.ts:331-333` · `src/session.ts:73-77`

**Code**
```ts
// commands.ts:331-334
  } catch {
    // appendEntry not available — marker not persisted; resume may
    // restore tools from before the reset. Non-critical for v1.
  }
```
```ts
// session.ts:73-77
    if (details.activated.length === 0 &&
        details.query === "/toolbelt reset") {
      break;
    }
```

**Why**
`handleReset` produces a reset-marker receipt via `appendEntry` that `restoreFromBranch` depends on to stop its backwards scan. The empty `catch` block silently swallows any failure — if `appendEntry` is unavailable or throws, the marker is never written. Without it, `restoreFromBranch` scans through pre-reset receipts, restoring tools the user reset. On resume, this effectively undoes the reset.

**Fix**
Log or warn on `appendEntry` failure so the author knows the reset marker wasn't persisted, or gate the `setActiveTools` call behind persistence success.

### Q2 🟡 Closure state mutated outside `session_start` gate `[precedent-weighted]`

**Where**
`src/index.ts:118`

**Code**
```ts
// index.ts:118
      currentEffectiveConfig = isEnabled(fresh) ? fresh : null;
```

**Why**
The closure variable `currentEffectiveConfig` is reassigned in the `/toolbelt` command handler's hot-reload path. This is the only mutation site outside `session_start`, which is the designated gate for all active-set changes. If the gate logic evolves, this side-channel bypass could produce stale or inconsistent state.

**Fix**
Route the post-command config refresh through the same validation path as `session_start`, or move it into a shared helper.

## Precedents

_No git history — this is the initial commit. Lessons drawn from design artifacts:_

**Recurring lessons (most → least frequent)**

1. **Runtime contract stability is the #1 risk** — Toolbelt depends on Pi's additive-detection guard (`wrapper.js:17-29`). If it changes, search activations silently degrade to full-list replacement. Pin the minimum Pi version.
2. **Fail-soft is a chain, not a single check** — Four consecutive config layers must all return `undefined` on failure. A single `throw` breaks the disabled-mode invariant.
3. **Reset is a heavy operation** — Every `/toolbelt reset` busts the provider's cached prompt prefix. Document this latency cost.
4. **Unused dependencies evade plan review** — `typebox` was not in the plan, not caught until validation. Add a dependency audit step before publish.
5. **Test the no-match path explicitly** — No-threshold-clearing queries must return near-misses and leave the active set unchanged. Existing integration tests cover this.
6. **Branch-scoped restoration is correct but surprising** — Navigating to an old session branch restores tools from that branch, including tools the user reset on main.
