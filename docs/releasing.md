# Releasing pi-toolbelt

Local, inspectable release flow. git-cliff owns generated `CHANGELOG.md`; humans do not edit that file. Preparation mutates the working tree only. Commit, tag, push, and `npm publish` stay manual.

## Prerequisites

- Clean git working tree on the branch you intend to release
- Node.js `>=20` and a full `npm install` (devDependencies include pinned `git-cliff` and `semver`)
- Write access for the git remote and npm publish rights for the package
- Intended product commits already on the branch, using Conventional Commits:
  - User-facing work: `feat:` / `fix:` subjects
  - Breaking work: `feat!` / `fix!` (or other type with `!`) plus a `BREAKING CHANGE:` footer for migration detail
- Package version in `package.json` is the source for the **initial** release when no `vX.Y.Z` tags exist

## Preview release notes (non-writing)

Shows commits since the latest matching version tag (or the full public history when none exist). Does not create or modify files.

```bash
npm run changelog:preview
```

Confirm `feat`, `fix`, and breaking entries look right. Routine `chore` / `refactor` / `docs` / `test` / `style` / `ci` commits should be absent unless they are breaking. Normal lines come from commit subjects; migration text comes from `BREAKING CHANGE:` footers only.

## Prepare the release tree

Pass exactly one stable SemVer `X.Y.Z` (no `v` prefix, no prerelease, no build metadata). The command does **not** pick a version for you.

```bash
npm run release:prepare -- 0.1.0
```

What it does, in order:

1. Rejects missing/extra/malformed versions
2. Requires repository root and a clean working tree
3. Version rules:
   - **No** `vX.Y.Z` tags yet: only the package's existing version is allowed (first release)
   - **After** tags exist: target must be strictly greater than the highest `vX.Y.Z` tag **and** greater than the current `package.json` version
4. Runs `npm run check`
5. Updates `package.json` and `package-lock.json` via `npm version` with commit/tag creation disabled
6. Writes versioned `CHANGELOG.md` with the local `git-cliff` binary and root `cliff.toml` (completed release section only; no live Unreleased section left in the file)
7. Runs `npm pack --dry-run`
8. Stops. No commit, tag, push, or publish.

If a stage after mutation fails, the script exits nonzero, names the failed stage, and leaves the partial diff for inspection. It never stashes, resets, checks out, restores, or cleans automatically.

## Inspect

```bash
git status
git diff
```

Check that:

- `package.json` / `package-lock.json` versions match the target
- `CHANGELOG.md` is a completed release entry for that version (generated by git-cliff only)
- Pack dry-run listed the intended publish surface (`src/`, `README.md`, `LICENSE`, `CHANGELOG.md`) and not repo-only paths (`docs/`, `cliff.toml`, `scripts/`, OpenSpec, `.rpiv/`)

## Manual release commit

Stage only the release files, then commit:

```bash
git add package.json package-lock.json CHANGELOG.md
git commit -m "chore(release): X.Y.Z"
```

Use the real version in the subject. Do not hand-edit `CHANGELOG.md` before committing.

## Annotated tag

```bash
git tag -a vX.Y.Z -m "vX.Y.Z"
```

Tags must match `v` + the same stable SemVer prepared above.

## Push

```bash
git push origin HEAD
git push origin vX.Y.Z
```

## Publish

From the same clean, tagged commit:

```bash
npm publish
```

Confirm the npm package page and install path (`pi install npm:pi-toolbelt`) after publish.

## Ownership rules

| Artifact | Owner |
|---|---|
| Commit history (Conventional Commits + breaking footers) | Humans |
| `cliff.toml`, `changelog:preview`, `release:prepare` | Repo tooling |
| Generated `CHANGELOG.md` | **git-cliff exclusively** - do not edit by hand |
| Release commit, annotated tag, push, `npm publish` | Human operator |

Regenerate notes by fixing commits (or preparing a follow-up release), not by patching `CHANGELOG.md`.
